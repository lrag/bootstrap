1. Campos de texto: form-control

Bootstrap no cambia cómo funciona un formulario: sigue siendo HTML. Solo da estilo con clases. Sin clase, cada navegador dibuja el campo a su manera y es un elemento en línea.

Sin clases

form-label + form-control

ClaseVa enQué hace
form-controlinput, textareadisplay: block, width: 100%, relleno, borde y esquinas; borde azul y halo al tener el foco
form-labellabelSolo un margin-bottom: .5rem
form-textun div debajoTexto de ayuda pequeño y atenuado
No compartiremos el correo con nadie.
<label for="email" class="form-label">Correo electrónico</label>
<input type="email" class="form-control" id="email" aria-describedby="email-ayuda">
<div id="email-ayuda" class="form-text">No compartiremos el correo con nadie.</div>
El for del label coincide con el id del campo: al hacer clic en la etiqueta el cursor entra en el campo, y el lector de pantalla lee la etiqueta. aria-describedby hace que también lea la ayuda. El placeholder no sustituye a la etiqueta: desaparece al escribir y tiene poco contraste.

2. Tipos de input y textarea

form-control sirve para todos los input de texto. El type lo pone HTML y cambia el teclado del móvil y lo que valida el navegador. El textarea también lleva form-control; rows fija la altura. En type="color" se añade form-control-color, para que no se estire a todo el ancho.

3. Tamaños y estados

form-control-lg y form-control-sm cambian altura, relleno y letra (en las listas, form-select-lg y -sm).

4. Listas: form-select

En un <select> va form-select en lugar de form-control: dibuja su propia flecha. Con multiple o size se convierte en una lista con varias filas visibles. Una primera opción con selected disabled hace de «Elige una opción».

5. Checkbox y radio

Bootstrap dibuja la casilla entera (igual en todos los navegadores, con el color primary). Siempre tres piezas:

<div class="form-check">                                   <!-- deja sitio a la izquierda -->
  <input class="form-check-input" type="checkbox" id="acepto">
  <label class="form-check-label" for="acepto">Acepto las condiciones</label>
</div>

checkbox: casillas independientes. radio: solo una del grupo, que lo forma el mismo name. fieldset + legend dan título al grupo (el lector de pantalla lee el legend antes de cada opción). form-check-inline las pone en línea y form-check-reverse pasa la casilla a la derecha.

6. Switches y checks con aspecto de botón

form-switch en el contenedor de un checkbox lo dibuja como interruptor. Sigue siendo un checkbox; role="switch" hace que el lector de pantalla lo anuncie como interruptor. Para opciones que se aplican al momento.

btn-check oculta el input y el label lleva las clases de botón: al marcarlo, el botón aparece pulsado. Aquí el label va después del input y sin div.form-check.

btn-check (checkbox)

btn-check (radio) en un btn-group

  <input class="form-check-input" type="checkbox" role="switch" id="notif">

7. Deslizadores: form-range

Un <input type="range"> con form-range ocupa todo el ancho y se ve igual en todos los navegadores. min y max marcan los extremos (0 y 100 por defecto) y step el salto. El deslizador no muestra su valor: lo escribimos al lado con JavaScript en el evento input. 

document.getElementById('volumen').oninput = () => {
  document.getElementById('valor-volumen').textContent = document.getElementById('volumen').value
}

8. Grupos de entrada: input-group

Un div.input-group pega al campo textos (input-group-text), iconos o botones, como una sola pieza. Es un contenedor flex: el campo crece y lo demás se queda a su tamaño, y Bootstrap quita las esquinas redondeadas entre piezas. El tamaño de todo el grupo se cambia con input-group-lg o input-group-sm.

9. Etiquetas flotantes: form-floating

La etiqueta empieza dentro del campo y, al entrar o escribir, sube y se hace pequeña. Tres reglas:

  • El input va antes del label.
  • El input necesita un placeholder, aunque no se vea: Bootstrap usa :placeholder-shown para saber si está vacío.
  • El label no lleva form-label.

Sin placeholder: la etiqueta se queda arriba

Dentro de un input-group

<div class="form-floating">
  <input type="email" class="form-control" id="email" placeholder="nombre@ejemplo.com">
  <label for="email">Correo electrónico</label>
</div>
En un textarea flotante, rows no funciona: la altura se fija con style="height: …". En un select la etiqueta siempre está arriba, porque un select nunca está vacío.

10. La rejilla en los formularios

Bootstrap no tiene un sistema propio para colocar campos: se usa la rejilla de siempre.

Varios por filaform.row.g-3 y columnas col-md-6, col-12…: en el móvil se apilan
Horizontal (etiqueta a la izquierda)Cada campo en un row mb-3; etiqueta col-sm-3 col-form-label y campo en col-sm-9
En línearow g-2 align-items-center con columnas col-auto; etiquetas con visually-hidden
Campo que crece y botón a su tamañocol + col-auto

form.row.g-3 con col-md-*

Horizontal: col-form-label (abajo) frente a form-label (primera fila)

En línea: col-auto · y col + col-auto

col-form-label da a la etiqueta el mismo relleno vertical que al campo, para que el texto quede a la misma altura. Sin g-3 en la fila, al apilarse en el móvil los campos quedarían pegados.

11. Validación

Quien valida es el navegador, con los atributos de HTML5 (required, type="email", minlength, min/max, pattern). Bootstrap no valida nada: pinta en verde o rojo lo que el navegador ya ha decidido y muestra nuestros mensajes en lugar de sus globos.

PiezaPara qué
novalidate en el formEl navegador sigue validando, pero no muestra sus globos ni bloquea el envío
was-validated en el form (con JavaScript, al enviar)Bootstrap pinta cada campo según :valid (verde) o :invalid (rojo)
invalid-feedback / valid-feedbackMensajes que solo se ven si el campo es inválido / válido. Van después del campo y como hermanos
is-invalid / is-valid en el campoMarcar a mano, sin depender del navegador (errores que decide el servidor)
invalid-tooltip / valid-tooltipEl mensaje como globo; el contenedor necesita position-relative
has-validation en el input-groupLas esquinas quedan bien con el mensaje dentro del grupo

  formAlta.onsubmit = (evento) => {

¿Por qué esperar a was-validated? Porque :invalid se cumple desde que carga la página: un campo required vacío ya es inválido, y el formulario aparecería en rojo antes de escribir nada.
