1. Dos caminos: variables CSS o Sass

Variables CSS (--bs-*)Sass ($primary…)
InstalarNadaNode.js, y con npm bootstrap y sass
Cuándo actúaEn el navegador (se pueden cambiar con JavaScript)Al compilar: genera un CSS nuevo
AlcanceSolo lo que Bootstrap dejó en variablesTodo, incluidos los tonos derivados (hover, foco, subtle, modo oscuro)
Colores nuevosA mano, clase a claseUna entrada en un mapa genera todas las clases
Quitar lo que no se usaNoSí, con la importación selectiva

En la práctica se combinan: Sass para la marca (colores, fuentes, esquinas) y variables CSS para ajustes puntuales.

2. Variables CSS globales

Se redefinen en :root (o en un contenedor, porque se heredan), en un CSS cargado después del de Bootstrap. 

:root {
  --bs-primary-rgb: 194, 65, 12;
  --bs-link-color-rgb: 194, 65, 12;
  --bs-border-radius: .75rem;
  --bs-body-font-family: "Nunito", system-ui, sans-serif;
}

Con las variables redefinidas

Lo que no cambia: btn-primary, el foco de los campos o alert-primary tienen sus colores escritos en el CSS compilado (--bs-btn-bg: #0d6efd), y el hover es un tono que Sass calculó al compilar. Por eso bg-primary y text-primary usan --bs-primary-rgb (para poder aplicar bg-opacity-*), pero el botón no. Para cambiar primary en todas partes hace falta Sass.

3. Variables CSS de componente

Cada componente dibuja con sus variables (.btn lee --bs-btn-bg, --bs-btn-color, --bs-btn-hover-bg…), y las clases de color solo les dan valor. Una clase propia puede hacer lo mismo. La lista de variables de cada componente está en su página de la documentación, apartado CSS → Variables. 

.btn-custom {
  --bs-btn-color: #fff;
  --bs-btn-bg: #c2410c;
  --bs-btn-border-color: #c2410c;
  --bs-btn-hover-bg: #9a3412;
  --bs-btn-hover-border-color: #9a3412;
  /* active, focus, disabled... */
}

4. Sass desde cero

Sass es un preprocesador: se escribe en SCSS (CSS con extras) y el compilador lo convierte en CSS normal. Bootstrap está escrito en Sass. Todo CSS válido es SCSS válido.

HerramientaSCSSPara qué
Variables$color-marca: #c2410c;Un valor con nombre; desaparece al compilar
Anidamiento.ficha { h3 { … } &:hover { … } }Genera .ficha h3 y .ficha:hover
Mixins@mixin caja-color($fondo) { … } / @include caja-color(red);Bloques de declaraciones reutilizables, con parámetros
Funcionesmix(#000, $color-marca, 20%)Calcular valores (Bootstrap: tint-color(), shade-color(), color-contrast())
Mapas$estados: ("pendiente": #b45309, …);Parejas clave: valor
Bucles@each $nombre, $color in $estados { .estado-#{$nombre} { … } }Una clase por entrada del mapa
 
$color-marca: #c2410c;
$estados: ("pendiente": #b45309,
           "enviado":   #1d4ed8,
           "entregado": #15803d);

@mixin caja-color($fondo) {
  background-color: $fondo;
  color: #fff;
  border-radius: .75rem;
  padding: .5rem 1rem;
}

.boton-marca {
  @include caja-color($color-marca);
  border: 0;
  &:hover { background-color: mix(#000, $color-marca, 20%); }
}

@each $nombre, $color in $estados {
  .estado-#{$nombre} { @include caja-color($color); }
}

Resultado (CSS compilado)

.ficha

Borde y título del color de la marca; fondo teñido al pasar el ratón.

.estado-pendiente .estado-enviado .estado-entregado
Así genera Bootstrap btn-primary, btn-success… a partir del mapa $theme-colors, y m-0…m-5 a partir de $spacers.

5. El proyecto con npm

Estructura (carpeta sass/ del workspace)

sass/
├── package.json
├── node_modules/        ← npm install
│   ├── bootstrap/scss/  ← las fuentes de Bootstrap
│   └── sass/            ← el compilador
├── scss/                ← lo que escribimos
│   ├── tema.scss
│   └── ...
└── css/                 ← lo que genera el compilador

Instalación

npm init -y
npm install bootstrap@5.3.8
npm install --save-dev sass@1.77.8

Scripts de package.json

"css":     "sass --load-path=node_modules --quiet-deps scss:css",
"vigilar": "sass --load-path=node_modules --quiet-deps --watch scss:css",
"css:min": "sass ... --style=compressed --no-source-map scss:css/min"
OpciónPara qué
scss:cssCompila cada .scss de scss/ en un .css de css/ (los parciales, _nombre.scss, no)
--load-path=node_modulesPermite escribir @import "bootstrap/scss/bootstrap"
--quiet-depsCalla los avisos del código de Bootstrap (no es nuestro)
--watchSe queda esperando y recompila al guardar
--style=compressedCSS minimizado, sin espacios ni comentarios
¿Por qué sass@1.77.8? Las versiones recientes de Sass necesitan un Node.js más nuevo que el 20.11 del aula y avisan de que @import se va a retirar: Bootstrap 5.3 lo usa en todas sus fuentes, así que saldrían cientos de avisos.

6. Compilar Bootstrap con variables propias

scss/tema.scss

$primary:   #c2410c;
$secondary: #334155;

$font-family-sans-serif: "Nunito", system-ui, sans-serif;
$headings-font-weight:   700;
$border-radius:          .75rem;
$link-decoration:        none;

@import "bootstrap/scss/bootstrap";

Resultado

text-primary · enlace · text-bg-primary

alert-primary: los tonos subtle y emphasis salen de $primary.

Nuestras variables van antes del @import. Todas las de Bootstrap llevan !default ($primary: $blue !default;): «este valor, salvo que ya tenga uno». Cuando Bootstrap llega a esa línea, $primary ya vale #c2410c y la respeta.

El texto del botón (blanco o negro) lo elige color-contrast(): el que cumpla un contraste de 4.5 ($min-contrast-ratio) con el fondo. Con un $primary claro, los botones llevarían texto negro. Las variables están en node_modules/bootstrap/scss/_variables.scss y en la documentación de cada componente, apartado Sass. Nunca se edita nada dentro de node_modules.

8. Mapas: $theme-colors y $spacers

Definir $theme-colors antes de Bootstrap lo sustituye entero. Para añadir una entrada, se importa primero solo la configuración (crea los mapas sin generar CSS), se modifican, y al final se importa Bootstrap entero:

scss/tema-mapas.scss (resumido)

@import "bootstrap/scss/functions";

$primary: #c2410c;
$oferta:  #7e22ce;

@import "bootstrap/scss/variables";
@import "bootstrap/scss/variables-dark";

$theme-colors: map-merge($theme-colors, ("oferta": $oferta));
$spacers:      map-merge($spacers, (6: $spacer * 5));

@import "bootstrap/scss/maps";

// tonos -subtle y -emphasis (y modo oscuro) para alerts y list groups
$theme-colors-text: map-merge($theme-colors-text,
                      ("oferta": shade-color($oferta, 60%)));
// ... bg-subtle, border-subtle, sus versiones -dark
// ... y $utilities-bg-subtle, $utilities-text-emphasis-colors,
//     $utilities-border-subtle para las utilidades

// Bootstrap entero: vuelve a importar variables y maps,
// pero con !default respeta lo que ya tiene valor
@import "bootstrap/scss/bootstrap";

9. Importación selectiva

En lugar de bootstrap.scss entero, se importan solo las partes que usa la web, en el mismo orden:

// Configuración: siempre (no genera CSS por sí sola)
@import "bootstrap/scss/functions";
// ...nuestras variables...
@import "bootstrap/scss/variables";
@import "bootstrap/scss/variables-dark";
@import "bootstrap/scss/maps";
@import "bootstrap/scss/mixins";
@import "bootstrap/scss/utilities";

// Base
@import "bootstrap/scss/root";
@import "bootstrap/scss/reboot";
@import "bootstrap/scss/type";

// Maquetación y componentes que se usan
@import "bootstrap/scss/containers";
@import "bootstrap/scss/grid";
@import "bootstrap/scss/buttons";
@import "bootstrap/scss/card";

// Utilidades
@import "bootstrap/scss/utilities/api";

Lo que más pesa son las utilidades: cada familia con sus seis versiones responsive. Se recortan con la API de utilidades (sesión 4) o con los $enable-*.
Lo que no se importa no existe: un class="table" o un class="alert" se quedan sin estilo. Algunas partes dependen de otras (los grupos de botones necesitan buttons y button-group; la navbar, nav).

10. Práctica

Tema de la tienda

  1. En la carpeta sass/, npm install y npm run vigilar.
  2. Crear scss/mi-tema.scss con la paleta de la marca ($primary, $secondary), una fuente de Google Fonts y esquinas propias.
  3. Añadir el color "oferta" a $theme-colors y usar btn-oferta y text-bg-oferta en las cards de productos.
  4. Enlazar sass/css/mi-tema.css en la landing en lugar de bootstrap.min.css.
  5. Comprobar el modo oscuro: los tonos -subtle y -emphasis también deben verse bien.
  6. Opcional: una versión selectiva con solo lo que usa la landing, y comparar el tamaño con npm run css:min.
