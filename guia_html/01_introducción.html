1. ¿Qué es Bootstrap?

Bootstrap es un framework de front-end de código abierto, creado en Twitter en 2011, que reúne CSS y JavaScript listos para usar. Permite maquetar interfaces responsive y coherentes aplicando clases en el HTML, sin escribir apenas CSS propio.

Rejilla

Sistema de 12 columnas basado en flexbox con seis breakpoints, pensado mobile-first.

Utilidades

Clases de una sola responsabilidad: espaciado, color, flex, bordes, sombras, visibilidad…

Componentes

Navbar, cards, modales, formularios, carrusel… con estilos y comportamiento incluidos.

Personalización

Variables CSS --bs-* y código fuente en Sass para adaptarlo a cualquier marca.

3. La unidad rem

rem (root em) es una unidad relativa al tamaño de letra del elemento raíz, es decir, de <html>: 1rem = el font-size de <html>. Es CSS puro, no tiene nada que ver con Bootstrap, pero Bootstrap la usa en casi todo, así que conviene entenderla antes de empezar.

Los navegadores usan 16 px por defecto, así que normalmente:

rempx (base 16)
0.25rem4 px
0.5rem8 px
1rem16 px
1.5rem24 px
3rem48 px
Accesibilidad. Si cambia el font-size de <html>, cambia todo lo que esté medido en rem. Eso ocurre, por ejemplo, cuando alguien aumenta el tamaño de letra en la configuración del navegador porque ve mal: con rem el diseño crece entero, en proporción y sin descuadrarse; con px se queda igual.

rem frente a px

Con la base de 16 px, 10rem = 10 × 16 = 160 px, y 1.5rem = 24 px, pero solo mientras la base sea 16 px. Los botones de la demo simulan la preferencia del navegador cambiando el font-size de <html> (afecta a toda esta página): la barra en rem crece o encoge, la de px se queda igual.

Ahora mismo 1rem = 16 px

width: 10rem
width: 160px

Texto con font-size: 1.5rem

Texto con font-size: 24px

document.documentElement.style.fontSize = '20px'

rem frente a em

em es relativo al tamaño de letra del elemento padre, así que al anidar se acumula: 1.2em dentro de 1.2em dentro de 1.2em = 1.2 × 1.2 × 1.2 = 1.728 veces la base. rem siempre mira a <html>: aunque lo anidemos, 1.2rem es siempre 1.2 veces la base. Por eso rem es más predecible.

1.2em dentro de 1.2em
1.2em dentro de 1.2em dentro de 1.2em
1.2rem
1.2rem dentro de 1.2rem
1.2rem dentro de 1.2rem dentro de 1.2rem

Bootstrap usa rem

Los márgenes y rellenos (m-*, p-*), los gutters y los tamaños de letra de Bootstrap están en rem. Su escala de espaciado: 1 → 0.25rem (4 px), 2 → 0.5rem (8 px), 3 → 1rem (16 px), 4 → 1.5rem (24 px), 5 → 3rem (48 px). Al cambiar la base con los botones de arriba, estas cajas cambian su relleno en proporción al texto.

p-2
p-3
p-4
p-5
Excepción: los breakpoints (576, 768, 992… px) y los anchos de los contenedores (540, 720, 960… px) están en px, no en rem.

4. Instalación

Opción A · CDN

La más rápida: no requiere instalar nada. Ideal para prototipos y para empezar el curso.

En el <head>, primero el CSS:

<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css"
      rel="stylesheet">

Y después el JS (incluye Popper), también en el <head> y con defer:

<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"
        defer></script>
Opción B · npm

Para proyectos reales: control de versiones, Sass y compilación propia (lo veremos en la personalización).

npm init -y
npm install bootstrap@5.3

Los ficheros quedan en node_modules/bootstrap/:

  • dist/css/bootstrap.min.css → CSS compilado
  • dist/js/bootstrap.bundle.min.js → JS con Popper
  • scss/ → código fuente Sass
Opción C · Copia local descargada

Se descarga el CSS y el JS compilados desde getbootstrap.com, se copian en una carpeta del proyecto (en el curso, recursos/bootstrap/) y se enlazan con rutas relativas. Funciona sin conexión y no depende de un servidor externo, pero las actualizaciones son manuales. 

<link href="recursos/bootstrap/css/bootstrap.min.css" rel="stylesheet">
<script src="recursos/bootstrap/js/bootstrap.bundle.min.js" defer></script>
¿bundle o no bundle? bootstrap.bundle.min.js incluye Popper, necesario para dropdowns, tooltips y popovers. bootstrap.min.js no lo incluye y hay que cargarlo aparte.

5. Estructura de una plantilla base

<!doctype html>
<html lang="es" data-bs-theme="light">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mi primera página con Bootstrap</title>
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css"
        rel="stylesheet">
  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"
          defer></script>
</head>
<body>
  <div class="container">
    <h1>¡Hola, Bootstrap!</h1>
  </div>
</body>
</html>
  1. <!doctype html>: activa el modo estándar del navegador. Sin él, Bootstrap se ve mal.
  2. lang: idioma del documento, importante para accesibilidad y lectores de pantalla.
  3. data-bs-theme: modo de color de toda la página (light o dark).
  4. Meta viewport: imprescindible para que el diseño responsive funcione en móviles.
  5. CSS en el <head>: evita que la página se pinte sin estilos.
  6. JS en el <head> con defer: se descarga en paralelo sin bloquear el pintado y se ejecuta con el DOM completo.

El atributo defer y window.onload

Un <script> normal detiene la lectura del HTML hasta que se descarga y se ejecuta. Con defer, el fichero se descarga en paralelo sin bloquear el HTML y se ejecuta cuando el DOM está completo, respetando el orden de los scripts. Por eso el JS de Bootstrap puede ir en el <head>, justo después del CSS.

Nuestro propio código va en otro <script> del <head>, después del de Bootstrap. Como en ese momento los elementos del <body> todavía no existen, lo metemos en window.onload: se ejecuta cuando la página ha terminado de cargar. 

<script src="…/bootstrap.bundle.min.js" defer></script>
<script>
  window.onload = () => {
    document.getElementById('ancho').textContent = window.innerWidth
  }
</script>

El elemento <meta>

Etiqueta de metadatos: información sobre el documento que no se muestra en la página. Siempre va dentro del <head>, es un elemento vacío (no tiene contenido ni etiqueta de cierre </meta>) y cada una expresa una pareja nombre-valor con atributos (charset, name + content…). La meta charset va la primera para que tildes y eñes se lean bien.

La meta viewport

El viewport es el área visible donde el navegador pinta la página. Sin la meta viewport, el navegador del móvil simula una pantalla de escritorio de unos 980 px, pinta la página a ese tamaño y luego la reduce para que quepa: todo se ve diminuto y los breakpoints de Bootstrap creen que están en un escritorio (980 px es md, así que se activa md en lugar de xs).

Con width=device-width el ancho de la página es el del dispositivo en píxeles CSS, y con initial-scale=1 el zoom inicial es del 100 %. Los píxeles CSS no son los físicos de la pantalla: un iPhone de 1170 px físicos con densidad ×3 mide 390 px CSS.

La meta no hace la página responsive: solo hace que el navegador diga la verdad sobre su ancho, para que las media queries de Bootstrap (sm, md, lg…) puedan funcionar.
Prueba: en las herramientas de desarrollo (F12 → modo dispositivo), al borrar la meta viewport y recargar, la rejilla deja de adaptarse y el indicador de breakpoint de 03_Meta.html marca md en un móvil.

6. Modos de color con data-bs-theme

Desde la versión 5.3, el atributo data-bs-theme cambia los colores de todos los componentes. Se puede poner en <html> para toda la página o en un elemento concreto para solo esa zona. Bootstrap redefine sus variables CSS (--bs-body-bg, --bs-body-color, --bs-border-color…) para ese modo, y todos los componentes que las usan cambian de color a la vez, sin tocar ni una clase. Si quitamos el atributo, la página es clara: light es el valor por defecto.

Toda la página

Cambia el atributo del elemento <html>:

Valor actual: light

Solo un elemento

Esta card tiene data-bs-theme="dark", así que siempre es oscura.

<div class="card" data-bs-theme="dark">…</div>

Zona clara en página oscura

Al revés: con la página en oscuro, data-bs-theme="light" deja esta zona clara.

<div class="card" data-bs-theme="light">…</div>

Cambiar el modo con JavaScript

Basta con cambiar el atributo del elemento <html>. document es la raíz del árbol DOM, pero no es una etiqueta HTML; document.documentElement sí: es la etiqueta <html>. 

document.documentElement.setAttribute('data-bs-theme', 'dark')
document.documentElement.removeAttribute('data-bs-theme')

Cómo funciona por dentro

Es CSS normal: variables CSS declaradas en :root, leídas con var(), y selectores de atributo que aplican unas u otras según el valor del atributo. Lo vemos primero con un atributo inventado, modo, como en 04_Data_bs_theme.html: 

:root {
  --color-modo1: lightGreen;
  --color-modo2: darkGreen;
  --estilo-texto-modo1: uppercase;
  --estilo-texto-modo2: capitalize;
}
[modo=modo1] {
  color: var(--color-modo1);
  text-transform: var(--estilo-texto-modo1);
}
[modo=modo2] {
  color: var(--color-modo2);
  text-transform: var(--estilo-texto-modo2);
}
<span modo="modo1">modo 1</span>
<span modo="modo2">modo 2</span>
<span modo="modo1">
  <span>modo 1</span>
</span>
<span>modo</span>
modo 1 modo 2 modo 1 modo

El <span> interior del tercer ejemplo no tiene atributo, pero hereda el color y el text-transform de su padre; el último no tiene ningún antepasado con modo y se queda con los estilos normales. Bootstrap hace lo mismo con data-bs-theme (simplificado): 

:root, [data-bs-theme=light] {
  --bs-body-bg: #fff;
  --bs-body-color: #212529;
  --bs-border-color: #dee2e6;
}
[data-bs-theme=dark] {
  --bs-body-bg: #212529;
  --bs-body-color: #dee2e6;
  --bs-border-color: #495057;
}
body {
  background-color: var(--bs-body-bg);
  color: var(--bs-body-color);
}

Como las variables CSS se heredan, un data-bs-theme en un elemento concreto redefine las variables para él y sus descendientes: por eso funciona tanto en <html> como en una sola card. En el punto de modo claro y oscuro veremos cómo crear un selector de tema completo que recuerde la preferencia.

7. Práctica

Primera plantilla

  1. Crear una carpeta de proyecto y abrirla en VS Code.
  2. Crear un fichero index.html con la plantilla base del apartado 5.
  3. Abrirlo en el navegador y comprobar en F12 → Red que se cargan el CSS y el JS de Bootstrap.
  4. Añadir un párrafo con la clase lead y un botón con class="btn btn-primary".
  5. Cambiar data-bs-theme a dark y observar qué cambia.
  6. Opcional: instalar Bootstrap con npm, o descargar la copia local, y enlazar esos ficheros en lugar del CDN.
