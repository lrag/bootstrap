1. Lo que ya sabemos

En la sesión 1 (Introducción, apartado 7 y 04_Data_bs_theme.html) vimos que data-bs-theme="dark" en <html> pone toda la página en oscuro, que en un elemento solo afecta a esa zona, y que por dentro son variables CSS redefinidas con un selector de atributo. En la sesión 2 (08_C_Colores.html) vimos qué colores cambian con el modo (*-subtle, *-emphasis, body) y cuáles no (bg-primary, text-bg-*).

2. Una zona con otro modo

data-bs-theme solo redefine variables. Un <div> normal no las usa: su fondo sigue transparente y su texto conserva el color heredado del <body>. Solo cambia lo que hay dentro y sí las usa (un input, una card…). Para que la zona entera se pinte, se le añaden bg-body y text-body.

data-bs-theme="dark"

El bloque no cambia; el input sí.

data-bs-theme="dark" class="bg-body text-body"

Ahora toda la zona es oscura.

Uso típico: una navbar o un pie siempre oscuros. Y los componentes que tenían clase propia para el oscuro la cambian por el atributo:

bg-primary no es un error: un botón o una etiqueta pueden ser del color de la marca en los dos modos. El problema son los blancos, negros y grises fijos, y los colores escritos a mano en style="".

4. Logos e imágenes

Un logo con el texto en un color fijo casi negro desaparece sobre fondo oscuro. Dos soluciones:

  • SVG con fill="currentColor": toma el color del texto, que ya cambia con el modo. Los iconos de Bootstrap Icons son una fuente y lo hacen siempre.
  • Dos versiones (para fondo claro y para fondo oscuro) y CSS que muestra una u otra según data-bs-theme. Es lo que se hace con un PNG.

fill="#212529"

fill="currentColor"

dos versiones + CSS

.logo-para-oscuro { display: none; }
[data-bs-theme=dark] .logo-para-claro { display: none; }
[data-bs-theme=dark] .logo-para-oscuro { display: inline; }

/* Fotos: un poco menos de brillo en oscuro */
[data-bs-theme=dark] img.foto { filter: brightness(.85); }
<picture><source media="(prefers-color-scheme: dark)"> también elige imagen, pero según el sistema operativo, no según data-bs-theme: si el usuario elige Oscuro en la página con el sistema en claro, no cambia.

5. Las variables --bs-*

Todo el color de Bootstrap 5.3 sale de variables CSS en :root. El modo oscuro no cambia ninguna clase: da otros valores a las variables. Las muestras de la tabla son style="background: var(--…)" y cambian con el tema de la guía.

Las parejas -rgb: muchas variables tienen otra con los tres números sueltos. Las utilidades las usan para poder poner transparencia: .bg-body { background-color: rgba(var(--bs-body-bg-rgb), var(--bs-bg-opacity)) }.
En DevTools: F12 → Elementos → <html> → Estilos. En oscuro, la regla [data-bs-theme=dark] aparece encima y tacha los valores de :root. El panel Calculado da el valor final en cada elemento.

8. Variables de cada componente

Cada componente declara sus propias variables en su clase y las usa en sus propiedades: .btn { --bs-btn-bg: transparent; … background-color: var(--bs-btn-bg) }. La documentación de cada componente las lista en su apartado CSS → Variables. Para crear una variante, basta una clase que les dé valores, y otra regla para el oscuro.

9. Selector de tema con JavaScript

Un selector completo, como el de la documentación de Bootstrap, tiene tres opciones y recuerda la elección. Conviene distinguir dos valores:

ValorPosiblesDónde está
Tema elegidolight, dark, autolocalStorage
Tema aplicadolight, darkdata-bs-theme de <html>

Estado del selector de esta guía (arriba a la derecha)

Elegido: Sistema: Aplicado:

Automático: prefers-color-scheme

Es una media query que dice si el sistema operativo está en claro u oscuro. Desde JavaScript, window.matchMedia() devuelve un objeto con matches (true / false) y el evento change, que salta cuando el sistema cambia de modo.

Para probarlo sin tocar el sistema: DevTools → ⋮ → More tools → Rendering → Emulate CSS media feature prefers-color-scheme.

Recordar la elección: localStorage

Guarda texto en el navegador, por sitio, y no se borra al cerrar. Se ve en DevTools → Aplicación → Almacenamiento local.

localStorage.setItem('tema', 'dark')
localStorage.getItem('tema')     // 'dark' o null
localStorage.removeItem('tema')

14_C_Selector_tema.html (resumido): un manejador por botón, como en los ficheros del curso

window.onload = () => {
  const consultaOscuro = window.matchMedia('(prefers-color-scheme: dark)')

  const aplicarTema = () => {
    const elegido = localStorage.getItem('tema') || 'auto'
    let aplicado = elegido
    if (elegido === 'auto') {
      aplicado = consultaOscuro.matches ? 'dark' : 'light'
    }
    document.documentElement.setAttribute('data-bs-theme', aplicado)
    document.getElementById('btn-claro').classList.toggle('active', elegido === 'light')
    document.getElementById('btn-oscuro').classList.toggle('active', elegido === 'dark')
    document.getElementById('btn-auto').classList.toggle('active', elegido === 'auto')
  }

  const elegirTema = (tema) => {
    localStorage.setItem('tema', tema)
    aplicarTema()
  }

  document.getElementById('btn-claro').onclick = () => { elegirTema('light') }
  document.getElementById('btn-oscuro').onclick = () => { elegirTema('dark') }
  document.getElementById('btn-auto').onclick = () => { elegirTema('auto') }

  consultaOscuro.onchange = () => { aplicarTema() }

  aplicarTema()
}

10. Sin parpadeo: el script del <head>

window.onload se ejecuta cuando la página ya está cargada y pintada. Si el tema guardado se aplicara ahí, con Oscuro elegido la página se vería primero en claro y luego cambiaría: un fogonazo blanco en cada carga.

La solución, la misma que usa la documentación de Bootstrap, es un script mínimo al principio del <head>, sin defer y fuera de window.onload: se ejecuta en cuanto se lee, cuando ya existe <html> (document.documentElement) pero aún no se ha pintado nada. 

<head>
  <meta charset="utf-8">
  <title>…</title>
  <script>
    const temaInicial = localStorage.getItem('tema') || 'auto'
    if (temaInicial === 'auto') {
      document.documentElement.setAttribute('data-bs-theme',
        window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light')
    } else {
      document.documentElement.setAttribute('data-bs-theme', temaInicial)
    }
  </script>
  <link href="…/bootstrap.min.css" rel="stylesheet">
  <script src="…/bootstrap.bundle.min.js" defer></script>
  <script>
    window.onload = () => { /* botones, menú, onchange... */ }
  </script>
</head>
Excepción a la convención del curso (JavaScript en window.onload): este script es la única excepción justificada. Se mantiene lo más corto posible, solo pone el atributo, y en el fichero se explica con un comentario HTML. Para ver el problema, se mueve dentro de window.onload, se elige Oscuro y se recarga varias veces.

11. Un modo de color propio

data-bs-theme admite cualquier valor. Basta una regla [data-bs-theme=sepia] que redefina las variables (con sus parejas -rgb) para tener un tercer modo. Las reglas que Bootstrap tiene solo para el oscuro (icono del select, X de cerrar) no se aplican: se usan las de claro, así que funciona bien con modos parecidos al claro.

12. Práctica

Modo oscuro para la landing de la tienda

Sobre la landing de la práctica de la sesión 1 (navbar, cabecera destacada y secciones en rejilla):

  1. Repasar las clases de color fijo (bg-white, bg-light, text-dark, text-muted…) y cambiarlas por las que se adaptan.
  2. Un selector de tema en la navbar: dropdown con Claro / Oscuro / Automático y sus iconos; el icono del botón muestra la opción elegida.
  3. Guardar la elección en localStorage y aplicarla con un script mínimo en el <head>, sin parpadeo al recargar.
  4. Automático sigue al sistema y cambia sin recargar (matchMedia + change).
  5. El pie, siempre oscuro, con data-bs-theme="dark" y bg-body text-body.
  6. Logo en SVG con fill="currentColor".
  7. Un color de marca para los enlaces, distinto en cada modo, redefiniendo --bs-link-color y --bs-link-color-rgb.
  8. Opcional: un componente propio (por ejemplo, una ficha de oferta) cuyo CSS use solo variables --bs-*.
