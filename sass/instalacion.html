Instalación de Sass y Bootstrap con npm

Lo necesario para compilar Bootstrap desde Sass con un tema propio: Node.js, npm, los paquetes y los comandos.

  1. Requisitos: Node.js y npm
  2. Usar este proyecto (ya montado)
  3. Montar un proyecto desde cero

  5. Compilar

1. Requisitos: Node.js y npm

Node.js ejecuta JavaScript fuera del navegador, y trae npm, el gestor de paquetes: descarga librerías (Bootstrap, el compilador de Sass…) y las deja en la carpeta node_modules. Se instala la versión LTS desde nodejs.org.

Para comprobar que están instalados, en una terminal:

node -v
npm -v

Cada comando muestra un número de versión (por ejemplo, v20.11.1 y 10.2.4). Si dice que no reconoce el comando, Node.js no está instalado o hay que cerrar y volver a abrir la terminal.

2. Usar este proyecto (ya montado)

La carpeta sass/ ya tiene su package.json, que dice qué paquetes necesita. La carpeta node_modules no se guarda en Git (pesa mucho y se regenera), así que la primera vez hay que instalarla: 

cd sass
npm install

npm install, sin nada más, lee package.json (y package-lock.json, con las versiones exactas) e instala todo lo que pone. Al terminar, ya se puede compilar.

3. Montar un proyecto desde cero

Para un proyecto nuevo, en una carpeta vacía:

npm init -y
npm install bootstrap@5.3.8
npm install --save-dev sass@1.77.8
ComandoQué hace
npm init -yCrea package.json con valores por defecto (-y: sin hacer preguntas)
npm install bootstrap@5.3.8Descarga Bootstrap: las fuentes .scss, el CSS y el JavaScript compilados. Lo anota en dependencies
npm install --save-dev sass@1.77.8Descarga el compilador de Sass. --save-dev lo anota en devDependencies: solo hace falta para desarrollar, no para que la web funcione

Después, crear la carpeta scss/ con los ficheros propios y añadir los scripts a package.json. La estructura queda así:

sass/
├── package.json        → dependencias y scripts
├── package-lock.json   → versiones exactas instaladas (lo crea npm)
├── node_modules/       → lo que instala npm (no se edita ni se sube a Git)
│   ├── bootstrap/
│   │   ├── scss/       → las fuentes de Bootstrap
│   │   └── dist/       → el CSS y el JS ya compilados
│   └── sass/           → el compilador
├── scss/               → nuestros ficheros .scss
└── css/                → el CSS que genera el compilador
¿Por qué sass@1.77.8 y no la última? Las versiones recientes de Sass necesitan un Node.js más nuevo que el 20.11 del aula (fallan con ERR_REQUIRE_ESM) y avisan de que @import se va a retirar. Bootstrap 5.3 usa @import en todas sus fuentes, así que saldrían cientos de avisos. Con la 1.77.8 compila limpio.

4. Los scripts de package.json

Los comandos largos se guardan con un nombre corto en la sección scripts:

"scripts": {
  "css":     "sass --load-path=node_modules --quiet-deps scss:css",
  "css:min": "sass --load-path=node_modules --quiet-deps --style=compressed --no-source-map scss:css/min",
  "vigilar": "sass --load-path=node_modules --quiet-deps --watch scss:css"
}
OpciónPara qué
scss:cssCompila cada .scss de scss/ en un .css de css/. Los parciales (_nombre.scss) no generan fichero
--load-path=node_modulesBusca también en node_modules: así funciona @import "bootstrap/scss/bootstrap"
--quiet-depsCalla los avisos del código de Bootstrap (no es nuestro)
--watchSe queda esperando y recompila cada vez que se guarda un .scss (se para con Ctrl+C)
--style=compressedCSS minimizado: sin espacios ni comentarios
--no-source-mapSin el fichero .map (en producción no hace falta)

5. Compilar

Siempre desde la carpeta sass/:

ComandoResultado
npm run cssCompila todos los .scss en css/, con su .map
npm run vigilarLo mismo, y recompila al guardar. Lo cómodo mientras se trabaja
npm run css:minVersión minimizada, en css/min/, para publicar

Para compilar un solo fichero, se llama a Sass directamente con npx (ejecuta el sass de node_modules):

npx sass scss/ejemplo-sass.scss css/ejemplo-sass.css            → entrada y salida
npx sass --watch scss/ejemplo-sass.scss css/ejemplo-sass.css    → y recompila al guardar
npx sass scss/ejemplo-sass.scss                                 → sin salida: el CSS sale en la terminal
npx sass --load-path=node_modules --quiet-deps scss/tema.scss css/tema.css   → uno que importa Bootstrap

6. Enlazar el CSS en el HTML

El navegador nunca ve los .scss: se enlaza el CSS compilado en lugar de bootstrap.min.css. El JavaScript de Bootstrap no cambia.

<link href="sass/css/tema.css" rel="stylesheet">
<script src="recursos/bootstrap/js/bootstrap.bundle.min.js" defer></script>

También sirve el JavaScript que trae el paquete: sass/node_modules/bootstrap/dist/js/bootstrap.bundle.min.js.

7. Problemas habituales

MensajeCausa y solución
'npm' no se reconoce como un comandoNode.js no está instalado, o la terminal se abrió antes de instalarlo: cerrarla y abrir otra
Can't find stylesheet to importFalta --load-path=node_modules, o no se ha hecho npm install, o el comando no se lanza desde sass/
Error [ERR_REQUIRE_ESM] al ejecutar sassVersión de Sass demasiado nueva para el Node.js instalado: npm install --save-dev sass@1.77.8
Muchos Deprecation Warning sobre @import o funciones de colorVersión de Sass reciente con el código de Bootstrap 5.3: añadir --quiet-deps, o usar sass@1.77.8
Undefined function o Undefined variableOrden de los @import: functions antes que variables, y variables antes de usar sus mapas
Los cambios del .scss no se venNo se ha recompilado (o vigilar no está en marcha), o el HTML enlaza otro CSS, o la caché del navegador: Ctrl+F5
