Apuntes del curso práctico de Bootstrap 5.3: maquetación responsive, componentes y personalización del framework.

1. Introducción y entorno

Qué es Bootstrap, qué cambia respecto a la versión 4 y cómo preparar una plantilla base.

1.1. ¿Qué es Bootstrap?

Bootstrap es un framework de front-end de código abierto, creado en Twitter en 2011, que reúne CSS y JavaScript listos para usar. Permite maquetar interfaces responsive y coherentes aplicando clases en el HTML, sin escribir apenas CSS propio.

Rejilla

Sistema de 12 columnas basado en flexbox con seis breakpoints, pensado mobile-first.

Utilidades

Clases de una sola responsabilidad: espaciado, color, flex, bordes, sombras, visibilidad…

Componentes

Navbar, cards, modales, formularios, carrusel… con estilos y comportamiento incluidos.

Personalización

Variables CSS --bs-* y código fuente en Sass para adaptarlo a cualquier marca.

1.3. Instalación

1.3.1. Opción A: CDN

La más rápida: no requiere instalar nada. Ideal para prototipos y para empezar.

En el <head>:

<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css" rel="stylesheet">

El JavaScript (incluye Popper):

<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js" defer></script>

1.3.2. Opción B: npm

Para proyectos reales: control de versiones, Sass y compilación propia.

npm init -y
npm install bootstrap@5.3

Los ficheros quedan en node_modules/bootstrap/:

  • dist/css/bootstrap.min.css: CSS compilado.

  • dist/js/bootstrap.bundle.min.js: JavaScript con Popper.

  • scss/: código fuente Sass.

1.3.3. Descarga directa

También se pueden descargar los ficheros compilados y servirlos desde el propio proyecto, sin CDN ni npm:

<link href="recursos/bootstrap/css/bootstrap.min.css" rel="stylesheet">
<script src="recursos/bootstrap/js/bootstrap.bundle.min.js" defer></script>
Nota
 bootstrap.bundle.min.js incluye Popper, necesario para dropdowns, tooltips y popovers. bootstrap.min.js no lo incluye y habría que cargarlo aparte.

1.4. Estructura de una plantilla base

<!doctype html> <!--(1)-->
<html lang="es" data-bs-theme="light"> <!--(2)-->
<head>
  <meta charset="utf-8"> <!--(3)-->
  <meta name="viewport" content="width=device-width, initial-scale=1"> <!--(4)-->
  <title>Mi primera página con Bootstrap</title>
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css" rel="stylesheet"> <!--(5)-->
  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js" defer></script> <!--(6)-->
</head>
<body>
  <div class="container">
    <h1>¡Hola, Bootstrap!</h1>
  </div>
</body>
</html>

  1. Activa el modo estándar del navegador. Sin él, Bootstrap se ve mal.

  2. lang: idioma del documento, importante para accesibilidad. data-bs-theme: modo de color de toda la página.

  3. Codificación de caracteres. Debe ir la primera para que tildes y eñes se lean bien.

  4. Meta viewport: imprescindible para que el diseño responsive funcione en móviles.

  5. CSS en el <head>: evita que la página se pinte sin estilos.

  6. JavaScript con defer.

1.4.1. ¿Script en el <head> o al final del <body>?

Un <script> normal detiene el análisis del HTML hasta que se descarga y ejecuta. Hay dos formas de evitarlo:

Al final del <body>

Es lo que hace la plantilla oficial. El contenido ya está pintado cuando empieza la descarga y el DOM existe cuando se ejecuta.

En el <head> con defer

El script se descarga en paralelo mientras se analiza el HTML y se ejecuta cuando el documento está completo. Los scripts con defer respetan su orden de aparición.

1.5. El elemento <meta>

<meta> es el elemento de metadatos: información sobre el documento que no se muestra en la página y que leen el navegador, los buscadores o las redes sociales.

  • Va siempre dentro del <head>.

  • Es un elemento vacío (void element): no tiene contenido ni etiqueta de cierre.

  • Cada <meta> es una pareja nombre-valor expresada con atributos.

Atributo Para qué Ejemplo

charset

Codificación del documento

<meta charset="utf-8">

name + content

Metadato con nombre

<meta name="viewport" content="…​">

http-equiv + content

Simula una cabecera HTTP

<meta http-equiv="refresh" content="5">

property + content

Open Graph (redes sociales)

<meta property="og:title" content="…​">

Otros <meta name="…​"> habituales: description, author, robots y theme-color.

1.6. La meta viewport

El viewport es el área visible donde el navegador pinta la página.

Cuando aparecieron los smartphones, casi todas las webs estaban pensadas para escritorio. Para que no se vieran rotas, los navegadores móviles simulan un viewport de unos 980 px: pintan la página a ese tamaño y luego la reducen para que quepa en la pantalla.

<meta name="viewport" content="width=device-width, initial-scale=1">
width=device-width

El ancho de la página es el del dispositivo en píxeles CSS, no físicos. Un iPhone de 1170 píxeles físicos con densidad ×3 mide 390 px CSS.

initial-scale=1

Zoom inicial al 100 %.

Importante
 La meta no hace la página responsive: solo hace que el navegador diga la verdad sobre su ancho, para que las media queries de Bootstrap puedan funcionar.
Tabla 1. La misma página en un iPhone emulado
Sin meta viewport: 980 px, breakpoint md Con meta viewport: 390 px, breakpoint xs

Sin la meta, el diseño de escritorio se reduce hasta hacerse ilegible. Con ella, la página usa el ancho real y se activa el diseño móvil.

Consejo
 Para probarlo en las herramientas de desarrollo (F12 → modo dispositivo), el emulador debe estar como dispositivo móvil. En Chrome y Edge, en modo «Responsive» con tipo «Desktop» no se aplica la reducción: la página se maqueta a 980 px pero aparece a tamaño normal con scroll horizontal. Basta con elegir un modelo concreto (por ejemplo, «iPhone 12 Pro»).

1.7. Modos de color con data-bs-theme

Desde la versión 5.3, el atributo data-bs-theme fija el modo de color: light (por defecto) o dark. Bootstrap redefine sus variables CSS (--bs-body-bg, --bs-body-color, --bs-border-color…) y todos los componentes cambian de color a la vez, sin tocar ninguna clase.

En <html>

Afecta a toda la página.

En un elemento concreto

Solo cambia esa zona.

<html lang="es" data-bs-theme="dark">
...
<div class="card" data-bs-theme="dark">…</div>

Para cambiarlo con JavaScript basta con modificar el atributo del elemento <html>:

document.documentElement.setAttribute('data-bs-theme', 'dark');
Figura 1. La misma sección en modo claro y en modo oscuro

La card de la derecha tiene su propio data-bs-theme="dark", por eso es oscura en los dos casos.

1.8. Práctica: la primera plantilla

  1. Crear una carpeta de proyecto y abrirla en VS Code.

  2. Crear un fichero index.html con la plantilla base.

  3. Abrirlo en el navegador y comprobar en F12 → Red que se cargan el CSS y el JS de Bootstrap.

  4. Añadir un párrafo con la clase lead y un botón con class="btn btn-primary".

  5. Cambiar data-bs-theme a dark y observar qué cambia.

  6. Opcional: instalar Bootstrap con npm y enlazar los ficheros de node_modules en lugar del CDN.

2. Contenedores y breakpoints

Dónde empieza y acaba el contenido, en qué anchos cambia el diseño y por qué se piensa primero en el móvil.

2.1. ¿Qué es un contenedor?

El contenedor es el elemento de maquetación más básico de Bootstrap: una caja que envuelve el contenido, lo centra horizontalmente, le da un ancho máximo según el tamaño de pantalla y le añade un relleno lateral para que el texto no toque los bordes.

<body>
  <div class="container">
    <!-- todo el contenido aquí -->
  </div>
</body>
Centrado

margin-left: auto; margin-right: auto.

Ancho máximo

max-width distinto en cada breakpoint.

Relleno lateral

0.75rem por lado (la mitad del gutter de 1.5rem).

Imprescindible para la rejilla

Las .row tienen márgenes negativos que el relleno del contenedor compensa.

Nota
 Los contenedores se pueden anidar, pero casi nunca hace falta. Lo habitual es uno por sección (cabecera, contenido, pie) o uno solo para toda la página.

2.2. Los seis breakpoints

Un breakpoint (punto de ruptura) es un ancho de viewport a partir del cual el diseño puede cambiar. Bootstrap 5 define seis, y cada uno tiene un infijo que aparece en el nombre de las clases (col-md-6, d-lg-none, container-xl…).

Aviso

Los breakpoints se definen en Sass (mapa $grid-breakpoints), así que se pueden cambiar al compilar Bootstrap. Desde la 5.3 también están expuestos como variables CSS (--bs-breakpoint-md, etc.), aunque solo como información: las variables CSS no funcionan dentro de una media query.

2.3. Tipos de contenedor

.container

Ancho fijo que salta en cada breakpoint. Al 100 % solo en móvil (xs). El más habitual.

.container-fluid

Siempre al 100 % del ancho. Para paneles, dashboards o bandas a ancho completo.

.container-{breakpoint}

Al 100 % hasta ese breakpoint; a partir de él se comporta como .container.

2.5. El enfoque mobile-first

Bootstrap se diseña primero para el móvil y luego se va ampliando para pantallas mayores. Técnicamente significa que sus media queries usan min-width: una clase con infijo se aplica desde ese breakpoint hacia arriba, nunca hacia abajo.

Lo que hace Bootstrap por dentro (simplificado):

/* Sin infijo: desde 0 px (móvil) */
.text-center { text-align: center; }

/* md: desde 768 px hacia arriba */
@media (min-width: 768px) {
  .text-md-start { text-align: left; }
}

Cómo se usa en el HTML:

<p class="text-center text-md-start">
  Centrado en móvil, a la izquierda desde tablet
</p>

<div class="col-12 col-md-6 col-xl-4">
  Ancho completo → mitad → tercio
</div>

2.5.1. Cómo se lee una lista de clases responsive

  1. La clase sin infijo es el estilo base: el del móvil.

  2. Cada clase con infijo sobrescribe la anterior a partir de su breakpoint.

  3. Si un breakpoint no tiene clase, hereda la del breakpoint inferior más cercano.

El mismo párrafo con text-center text-md-start text-xl-end en tres anchos de ventana:

Figura 8. xs (400 px): centrado
Figura 9. md (800 px): a la izquierda
Figura 10. xl (1250 px): a la derecha
Consejo
 Por qué mobile-first: el móvil es la pantalla más limitada y hoy la más usada. Partir de lo sencillo y añadir complejidad es más fácil que recortar un diseño de escritorio.
Nota
 ¿Y hacia abajo? En Sass existe media-breakpoint-down(md), que genera max-width: 767.98px. Los .98 evitan que dos media queries coincidan en el mismo píxel.

2.6. Práctica: contenedores y breakpoints

  1. Crear una página con tres bloques: cabecera con .container-fluid, contenido con .container y pie con .container-lg, cada uno con un color de fondo distinto.

  2. Redimensionar la ventana y anotar en qué anchos cambia cada bloque.

  3. Añadir un título con text-center text-lg-start y comprobar en qué breakpoint cambia la alineación.

  4. Mostrar un mensaje solo en móvil con d-md-none y otro solo desde tablet con d-none d-md-block.
